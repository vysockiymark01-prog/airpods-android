# AirPods для Android

Нативное Android-приложение (Kotlin), переносящее часть iOS-only функций AirPods на Android:
заряд каждого наушника и кейса по отдельности, автопауза при извлечении из уха, переключение
режимов шумоподавления (Transparency / ANC / Auto). Работает через реверс-инжиниринг протокола
Apple Continuity/AACP — без root, без официального Apple API.

## Почему не PWA

Web Bluetooth не поддерживает пассивное фоновое сканирование BLE-рекламных пакетов и не даёт
открывать управляющее соединение без пользовательского жеста при каждом запуске — обе эти вещи
здесь обязательны. Поэтому это отдельное Android-приложение (Gradle/Kotlin), а не веб-обёртка.

## Как это работает технически

1. **Заряд и ear-detection** читаются пассивно из BLE-рекламного пакета Apple "Proximity Pairing"
   (company ID `0x004C`, message type `0x07`) — этот пакет транслируется открыто, ловит его любой
   сканер поблизости, подключение не требуется. См.
   `app/src/main/java/.../ble/ProximityPairingParser.kt` — там подробно расписан формат байтов.
2. **Переключение ANC** — НЕ через GATT-запись, как изначально предполагалось в ТЗ. По факту
   AirPods держат управляющий канал (AACP) на L2CAP connection-oriented channel (PSM `0x1001`)
   поверх уже установленного classic Bluetooth соединения (того самого, что используется для
   A2DP-звука) — не через отдельный BLE GATT-профиль. См. `ble/AacpController.kt`.
3. Таблица device ID → модель наушников и таблица command-байтов ANC вынесены в отдельные объекты
   (`ble/DeviceModel.kt`, `ble/AacpCommandTable.kt`) и поддерживают удалённое переопределение через
   `RemoteCommandTableStore` — если протокол для новой модели доуточнится после релиза, не нужно
   ждать обновления в Google Play.

## Источники протокола

Формат пакетов не был придуман с нуля — он независимо задокументирован несколькими
open-source проектами реверс-инжиниринга AirPods, здесь использованы только *факты о формате*
(байтовые смещения, ID моделей), а не их код:

- [OpenPods](https://github.com/adolfintel/OpenPods) — GPLv3
- [librepods (AAP)](https://github.com/librepods-org/librepods) и
  [kavishdevar/librepods](https://github.com/kavishdevar/librepods) — GPLv3
- [capod (d4rken-org)](https://github.com/d4rken-org/capod)

## Известные ограничения (честно, не приукрашивая)

- **AirPods Pro 3 не в таблице моделей.** На момент написания ни один открытый проект
  реверс-инжиниринга не опубликовал подтверждённый device ID или ANC-команды для Pro 3 — модель
  либо совсем новая, либо ещё не полностью изучена сообществом. Наушники с неизвестным ID всё
  равно получат корректный заряд и ear-detection (эта часть формата не зависит от модели), но
  силуэт будет обобщённым, а переключение ANC — отключено, пока байты не подтверждены (см.
  `RemoteCommandTableStore` для обновления без релиза в Store).
- Заряд обновляется не чаще, чем сами наушники его транслируют (~1 раз в минуту и реже),
  округление до 10% — это ограничение прошивки Apple, а не приложения. UI честно показывает
  "обновлено N мин назад".
- ANC-переключение — best-effort: если наушники не подтверждают приём команды на уровне протокола
  (что не задокументировано публично ни для одной модели), приложение может думать, что команда
  отправлена успешно, хотя реальный режим не изменился.
- Требует, чтобы наушники уже были подключены как аудио-устройство через системные настройки
  Bluetooth — приложение не заменяет процесс сопряжения.
- L2CAP-канал для ANC (`BluetoothDevice.createInsecureL2capChannel`) доступен с Android 10 (API 29);
  на более старых версиях доступен только заряд/автопауза.

## Точно недоступно (и не будет обещано пользователям)

Adaptive Audio, Personalized Volume, Conversation Awareness (обработка на чипе H2), Ear Tip Fit
Test, Precision Finding/UWB, Automatic Switching между Apple-устройствами — всё это либо требует
специализированного чипа Apple (H2/U1), либо завязано на iCloud/Handoff и физически недоступно
сторонним Android-приложениям.

## Сборка

Требуется Android SDK (compileSdk 35) — CI собирает автоматически на push через GitHub Actions
(`.github/workflows/android-build.yml`), т.к. в средах разработки этого проекта нет прямого
доступа к серверам Google для скачивания SDK/зависимостей.

- Debug APK собирается на каждый push/PR — доступен во вкладке Actions → артефакт `app-debug`.
- Release AAB (подписанный) собирается, если в секретах репозитория настроены
  `RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS`,
  `RELEASE_KEY_PASSWORD` — это уже сделано для основного релизного ключа проекта.

## Статус

MVP (заряд по отдельности + анимация + автопауза + темы) и Фаза 2 (переключение ANC) реализованы
на уровне кода; полноценное end-to-end тестирование возможно только на реальном устройстве с
настоящими AirPods — рекомендуется трек внутреннего тестирования Google Play.
